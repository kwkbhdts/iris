# Iris

Windows 向けの小さな通知領域ツール。通常権限で動かし、修飾キーなしの **F1** を手動で押すと、前面が `Claude.exe` / `firefox.exe` / `chrome.exe` / `ChatGPT.exe` の場合だけ、IME の従来の応答を確認して Unicode の `OK` と Enter を一度送ります。AutoHotkey は不要です。

`main` は初回の案内のみ、`dev` は開発用です。**IME 対応を通常版へ統合したこの版は実機での再確認が必要です。** 比較版での限定的な実測結果は後述します。

## 通常版の使い方

1. 他の Iris（通常版・診断版・試験版）をすべて終了し、`iris.exe` を一つだけ起動します。初期状態は有効です。
2. 対象アプリの**送信してよい入力欄**で、**空欄・未確定文字なし**を自分で確認してフォーカスします。
3. 修飾キーと Enter を離し、F1 を一度押します。入力・復元が終わるまでキー・マウスに触れないでください。長押し・処理中の連打では追加送信しません。
4. 通知領域アイコンから「有効」を切り替えるか「終了」を選べます。入力・復元を確認できなければ無効化して理由を表示します。入力・送信結果、キー状態、IME を手動確認してから再び有効にしてください。未完了処理がある間は再有効化できません。

**対象外・無効時・修飾キー付きでは通常の F1 を通します。** 押し始めの抑止／通過をキーアップまで維持します。診断・試験版の「全アプリで単独 F1 を抑止する」動作は通常版には持ち込みません。終了時にフックと通知領域アイコンを解除します。

## 通常版の IME とタイミング

| 段階 | 動作 |
| --- | --- |
| 元の legacy 応答が0 | オフ応答を再確認して入力。IME 切替・オン復元・復元待機は行わない。 |
| 元の legacy 応答が1 | 同じ IME ウィンドウへオフを要求し、0を読み返せた場合だけ入力。 |
| 状態取得失敗・不明 | 送信しない。無効化と理由表示。前面変更など入力前の取消だけなら何も送らない。 |
| OK → Enter | **追加待機なし**。Unicode O/K と Enter の押下・解放、6イベントを1回の SendInput に投入。 |
| 入力後の IME 復元 | 元が1かつ全6イベント投入の場合だけ、投入後**暫定100ms**待機し、条件が保持されればオンへ戻して1を読み返す。 |

IME の反映確認は応答の読み返しであり、固定の100ms待機ではありません。100msは**文字→Enter の間隔ではなく、復元前だけの実験値**です。比較版ではこの条件で動作しましたが、必要性・十分性は未立証で、アプリの入力消費完了を検出するものではありません。SendInput の成功は入力ストリームへの投入数を示すだけで、実際の入力先・チャット送信成功は保証しません。

## 取消・復元と制約

- **空欄・フォーカス・未確定文字なしは使用条件であり、検査しません。** TSF の実際の状態や未確定文字の有無を検出できるとは主張しません。従来の開閉応答0/1に基づく実験的な IME 制御です。変換途中の文字を残して使うと確定・取消などが起こる可能性があります。
- 対象は実行ファイル名だけで判定します。Firefox／Chrome の URL 判定はなく、全サイト・入力欄・アドレスバーが対象になり得ます。自動フォーカス、通知検知、承認の自動化はありません。実行ファイル名はセキュリティ上の本人確認ではありません。
- フック外で前面プロセス名を確認し、前面変更イベントと200msのタイマーで候補を更新します。切替直後など対象未確認の間は F1 を通すため、必要なら前面が落ち着いてから押し直してください。
- 入力・設定の前に前面／フォーカス HWND・PID・スレッド、実行ファイル名、IME ウィンドウと所有者、レイアウト、修飾キー、期限を再確認します。キーボード・マウス操作（移動を含む）や前面・フォーカス変更イベントを介入として記録し、元へ戻っても処理を再開しません。背景のフォーカスイベントでも保守的に中止する場合があります。
- **無効化・終了は新規入力を停止**します。IME を既にオフにした場合は、同じ対象・介入なし・期限内・現在の応答0を確認できるときだけ、一度復元を試みます。トレイを操作するマウス移動や前面変更自体も中止要因なので、その場合は自動復元せず手動確認を求めます。投入済みの場合、終了要求だけでは復元用100msを短縮しません。
- 各 IME メッセージの待ち時間は50ms、処理期限は F1 から500msです。期限切れでも作業が戻るまで予約を保持し、重複実行させません。無効化し、通知領域で手動確認を知らせ、作業が戻った時点で理由を表示します。終了待ちは最大約1秒、未確認なら通知して終了します。OS の応答やタイマーの時刻の厳密な保証はありません。
- 状態不明・対象移動・介入・タイムアウト・一部投入では盲目的に復元しません。入力失敗時の自動再送・追加 Enter・自動キー解放もありません。投入済みの入力や設定要求は取消できず、タイムアウトした要求が後から反映される可能性も残ります。**強制終了・クラッシュ時の復元は保証できません。**
- **SendInput は特定ウィンドウ宛てではないため、確認直後の切替や同一 HWND 内の入力欄変更による誤送信を完全には防げません。** 手動介入やフォーカス変更の完全な検出も保証しません。
- 自分の注入イベントは再処理せず、他の注入イベントも F1 のトリガーにはしません。他の注入は進行中処理の中止要因になります。管理者権限の対象への入力は UIPI により失敗する可能性があり、昇格や回避は行いません。
- 本文・タイトル・URL・変換中文字列・候補は収集しません。他プロセスの入力コンテキストを自プロセスの IMM API へ渡しません。フックが OS に解除された場合の自動復旧も保証しません。
- 自動起動、設定ファイル、汎用マクロ、通信機能はありません。起動時に既知の Iris ウィンドウとの重複を確認しますが、同時起動の競合を完全に防ぐ仕組みではありません。一つだけ起動してください。

Chrome と ChatGPT Desktop の追加対応は対象判定のみです。ローカルで実ファイル名 `chrome.exe` / `ChatGPT.exe` を確認しています。製品メタデータや OriginalFilename では判定せず、`codex.exe` は対象外です。両アプリでの入力送信・IME 復元は実機未確認で、既存の Claude／Firefox 実測結果を動作保証にはできません。診断・試験バイナリの対象は引き続き Claude／Firefox のままです。

## 利用者による実測範囲

入力比較版 **`3eb7609`** で、利用者が Claude Desktop と Firefox のそれぞれ半角・日本語入力を試し、`OK` の送信成功を確認しました。

- 元がオフ：6/6イベント投入、エラー0、IME 書き込みなし、文字→Enter 待機0ms。
- 元がオン：legacy 応答1→オフ確認0→6/6投入→復元前0→復元後1。変換モードは前後0x19、手動確認要求なし、処理時間は125ms。復元用の暫定待機100msを含む条件です。

この結果は当該環境・試験時の入力欄での利用者報告です。一般的な TSF の保証、全アプリ・全バージョン・全入力欄での成功、100msの必要性を示すものではありません。**トレイ版への統合後は、同じ2アプリ×2モードに加え、対象外 F1・有効無効・長押し・終了を再確認してください。** このクラウド環境から Windows 実機操作やチャット送信は行っていません。

## ビルドと検証

第一候補は Windows x64 と `x86_64-pc-windows-msvc`。ビルドには Rust と MSVC C++ ビルドツール／Windows SDK が必要です。

```sh
cargo fmt --check
cargo test --locked
cargo check --locked --bins --target x86_64-pc-windows-msvc
cargo build --locked --release --bins --target x86_64-pc-windows-msvc
```

出力は `target/x86_64-pc-windows-msvc/release/iris.exe`。`.cargo/config.toml` で CRT 静的リンクを指定し、追加ランタイム不要の単一 exe を目指します。Windows 標準 DLL は利用します。実際の DLL 依存関係は Windows ビルド後に確認が必要です。

Linux では `cargo test` が F1 の状態遷移と実行ファイル名判定を検証します。Windows 標準ライブラリを備えた Rust なら `cargo check --target x86_64-pc-windows-msvc` で Windows コードの型チェックも可能ですが、exe のリンクには別途 Windows 用のツール／ライブラリが必要です。

## CI と検証範囲

[GitHub Actions の Build](https://github.com/kwkbhdts/iris/actions/workflows/build.yml) は `main` / `dev` への push と、それらに向けた pull request で動きます。

- Linux ジョブ: `cargo fmt --check` とロジックテスト（通常版29件・診断版6件・切替試験版16件・入力比較版20件、共通処理の再実行を含む）を実行します。IME 状態分岐、復元前の実験待機、一部投入時の停止、重複防止、取消、古い通知、期限切れも対象です。
- Windows ジョブ: `x86_64-pc-windows-msvc` の release exe をビルドします。CRT 静的リンクは `.cargo/config.toml` の指定を使用します。
- exe は各 run の **Artifacts → iris-windows-x64** から取得できます（保存期間14日）。開発用成果物であり、リリース版ではありません。

各コミットの CI 成否は Actions で確認してください。依存バージョンは `Cargo.lock` に固定しています。Linux 上での整形・ロジックテスト・Windows 向け型チェックは確認済みですが、型チェックには exe のリンクや実行は含まれません。

**Windows CI のビルドは、通常版統合後の通知領域・フック・入力送信・日本語 IME の動作確認にはなりません。統合後の実機動作は未確認です。** CI は Iris の常駐開始や実際のチャット送信を行いません。

実機検証は、実際にチャットを送信しない Firefox のローカル HTML 入力欄などから始めてください。IME オン／半角（未確定文字なし）、長押し、連打、各修飾キー、対象外アプリ、前面切替、有効切替、終了後の F1、通常権限から高い権限の対象への失敗を確認します。Claude 固有の入力動作は別途、送信を許可した環境での確認が必要です。

通常版では特に、入力前の取消で送らないこと、復元待機中の介入で手動確認になること、取消後に対象へ戻っても古い処理が再開しないことを確認してください。投入済みの Enter は取り消せません。タイマー時刻やアプリのイベント処理は Linux のロジックテストでは検証していません。

## 読み取り専用の診断版

`iris-diagnostic.exe` は通常版とは別の実行ファイルです。文字入力・Enter 送信・IME の切替・未確定文字の確定や取消は行いません。診断版の実行で通常版の設定や入力処理を変更することはありません。

1. 通常版を通知領域の「終了」で閉じ、診断版を一つだけ起動します。診断中に通常版を起動しないでください。起動時には通常版との重複を確認しますが、その後の同時起動による入力送信は防げません。
2. 対象アプリの入力欄へ自分でフォーカスし、**半角 → 日本語入力（未確定文字なし）→ 未確定文字あり**の順に、各状態で単独 F1 を一度押します。各結果が表示されてから次に進みます。実際のチャット送信は不要です。
3. 診断ウィンドウの「結果を選択 → Ctrl+C」を押し、Ctrl+C でコピーします。必要なら各サンプルの状態を自分で添えて貼り付けてください。ウィンドウを閉じると終了してフックを解除します。

診断版が起動している間は、**対象外を含むすべてのアプリで単独 F1 を診断用に抑止**します。修飾キー付き F1 は通します。長押し・採取待ち中の連打・注入イベントでは追加採取しません。通常版の対象外 F1 の動作には変更ありません。

表示するのは F1 時点の前面／フォーカス HWND・PID・スレッド ID、実行ファイルのベース名、後続の問い合わせ時点のキーボードレイアウトと IME ウィンドウ情報、従来の IMM 互換問い合わせの生の応答です。プロセスの照会／メモリ読み取り権限はモジュールのベース名取得に使い、本文・タイトル・URL・ファイルのフルパス・変換中文字列・候補は収集しません。最新6件をメモリ上に表示するだけで、ファイル保存・通信・自動クリップボード操作は行いません。

IME 問い合わせは対象プロセス名とウィンドウの所有者を確認した上で、フック外の単一作業スレッドから行います。他プロセスの入力コンテキストを自プロセスの IMM 関数へ渡しません。各メッセージの待ち時間は50ms、結果採用の期限は F1 から500msです。遅れて戻った結果は破棄します。OS の処理や UI タイマーの実行時刻について厳密な時間保証はありません。

**生の応答が0でも「IME オフ」「未確定文字なし」とは判定しません。** 従来の問い合わせに対する現行 IME の対応は保証されず、TSF の実際のオン／オフと未確定文字の有無は常に不明と表示します。失敗・タイムアウト・未取得も不明です。レイアウトの値だけでも IME 状態は判断できません。採取前後のウィンドウ識別情報が一致しても、同じ HWND 内の入力欄変更や一瞬の前面切替は検出できず、全項目の同時取得も保証しません。

診断版は `target/x86_64-pc-windows-msvc/release/iris-diagnostic.exe` に出力されます。CI の追加成果物名は **iris-diagnostic-windows-x64** です。利用者の Claude／Firefox 実測では半角・日本語待機・変換途中の応答が0/1/1でしたが、未確定文字の有無は区別できず、TSF 状態も不明です。

## IME 切替・復元だけの試験版

**`iris-ime-trial.exe` は IME の状態を変更する実験版です。文字入力・Enter・チャット送信は一切行いません。** 通常版と読み取り専用診断版の動作は維持しています。利用者の Claude／Firefox 実測では legacy 応答1→0→1を観測しました。Firefox ではモード変化と日本語への復帰も目視確認されています。条件を変えた動作は保証しません。

1. **通常版 Iris と読み取り専用診断版を終了**し、試験版を一つだけ起動します。試験中に他の Iris を起動しないでください。
2. Claude Desktop または Firefox の**空の入力欄・未確定文字なし**を自分で確認してフォーカスします。今回は変換途中の文字を残して試さないでください。
3. 日本語入力をオンにし、修飾キーを離して F1 を一度押します。**結果が出るまでキー・マウスに触れないでください。** 半角での比較は状態変更を行わないことの確認です。
4. 結果が表示された後、「結果を選択 → Ctrl+C」でコピーします。最後に元の入力欄の IME 状態を自分で確認してください。手動確認が必要と表示されたら、自分で復元し、試験版を終了してください。再試験には再起動が必要です。

元の `legacy_open` が正確に1の場合だけ、同じ IME ウィンドウへ従来の `IMC_SETOPENSTATUS` によるオフ要求を送り、応答0を読み取った後に約100ms待ってオンへの復元を試みます。元が0・不明・取得失敗なら変更しません。現行 IME での設定コマンドの対応は保証されません。設定の生の戻り値0を候補とし、設定後の読み取り応答も照合します。`legacy_1_0_1_observed` は従来の応答の往復を観測した意味で、TSF の実際の状態や完全な復元の証明ではありません。変換モードは前後の観測だけで、書き戻しません。

各操作前に、前面・フォーカス HWND/PID/スレッド、対象の実行ファイル名、IME ウィンドウと所有者、レイアウト、経過時間を再確認します。キーボード・マウス操作（移動を含む）、前面・フォーカス変更イベントは内容を保存せず、試験への介入として扱います。移動後に元へ戻っても処理を再開しません。バックグラウンドのフォーカスイベントでも保守的に中止する場合があります。フック内で待機やプロセス・IME 問い合わせはせず、単一作業スレッドで一件ずつ処理します。

- オフ要求前の取消では書き込みません。
- オフ要求後は、介入なし・同じ対象／レイアウト・期限内・現在の応答0を再確認できた場合に限り、オンへの復元を一度だけ試みます。状態不明、対象移動、介入、タイムアウトでは盲目的に書き戻さず、手動確認を求めます。
- メッセージの待ち時間は各50ms、試験の期限は F1 から500msです。期限切れでも作業が戻るまで次の試験は開始しません。タイムアウトした設定要求も、後から反映される可能性を否定できません。待ち時間の制限は状態変更の取消ではありません。
- 終了要求は新規のオフを止め、既に変更した場合だけ上記条件で復元を試みます。×を押す操作自体も介入・前面変更となり、復元を中止する場合があります。作業の終了待ちは最大約1秒とし、未確認なら通知して終了します。OS の応答・タイマー時刻の厳密な保証はありません。
- **強制終了・クラッシュ時の復元は保証できません。** 未確定文字が残っていた場合には、切替で確定・取消などが起こる可能性があります。未確定文字の有無は検出せず、本文・URL・タイトル・変換中文字列・候補は収集しません。
- 同じ HWND 内の入力欄の切替、届かないイベント、確認直後の競合は完全には検出できません。手動操作の完全な識別や設定の原子的な復元は保証しません。結果が不明なら自動で再試行せず、終了・手動確認後に再起動してください。

起動中は全アプリの単独 F1 を抑止します。修飾付き F1 は通過しますが、試験中の修飾キー操作は取消要因です。結果は最新6件をメモリ上に表示するだけで、通信やファイル保存はしません。

CI の **Artifacts → iris-ime-trial-windows-x64** を展開し、`iris-ime-trial.exe` を使用します。通常版・読み取り専用診断版の成果物も引き続き生成します。ビルド出力は `target/x86_64-pc-windows-msvc/release/iris-ime-trial.exe` です。

## IME 対応の入力比較版

**`iris-input-trial.exe` は `OK` と Enter を実際に送る比較版です。** 通常版・読み取り専用診断版・切替試験版を変更せず、別 exe としています。`3eb7609` の限定的な実測結果は「利用者による実測範囲」に記載しています。一般的な動作保証ではありません。

1. **他の Iris の exe をすべて終了**して入力比較版を一つだけ起動します。試験中も同時起動しないでください。
2. Claude Desktop または Firefox の**送信してよい試験先**で、**空の入力欄・未確定文字なし**を自分で確認してフォーカスします。入力欄・URL・内容をツールは検査しません。
3. まず半角、次に日本語オンで比較します。各試験で修飾キーと Enter を離して F1 を一度押し、結果が出るまでキー・マウスに触れないでください。次の試験前にも空欄・未確定文字なしを確認します。
4. 入力・送信結果と終了後の IME モードを目視し、「結果を選択 → Ctrl+C」でログをコピーします。不明・失敗なら自動再試行は行われません。入力内容・送信結果・キー状態・IME を手動確認し、必要な復元後に比較版を終了してください。

タイミングは次の3点を分けています。

| 処理 | この比較版の条件 |
| --- | --- |
| IME 切替の反映確認 | 元の legacy 応答が1ならオフ要求後に0を読み返す。元が0なら書き込まず0を再確認。固定の反映待機は置かず、確認できなければ入力しない。TSF への反映保証ではない。 |
| OK → Enter | **追加待機0ms**。Unicode の O/K と Enter の押下・解放、合計6イベントを1回の SendInput で順に投入。文字と Enter の間に100msは置かない。 |
| 入力後 → IME 復元 | 元が1で全6イベントを投入できた場合だけ、SendInput から戻った後に**暫定100ms**待って条件付き復元。元が0なら切替・オン復元・復元待機はしない。 |

復元用100msは、即時復元の影響を分けて観察するための**必要性・十分性とも未確認の実験値**です。対象アプリの入力処理完了を検出する値でも必須仕様でもありません。SendInput の戻り値は入力ストリームに投入した数であり、アプリの消費・チャット送信成功を意味しません。ログでも `app_consumption=unknown` / `chat_send_success=unknown` と表示します。復元が処理より早い可能性は残ります。

対象は前面の `Claude.exe` / `firefox.exe` に限定し、前面／フォーカス HWND・PID・スレッド、IME の所有者、レイアウト、修飾キー、介入、期限を入力直前にも再確認します。未知の IME 応答は入力・設定の成功扱いにしません。注入イベントのうち自分のタグが付いたものは再処理・介入扱いせず、他の注入やキーボード・マウス操作、フォーカス変更は中止要因です。タグはセキュリティ上の本人確認ではありません。

元が1の場合の復元は、同じ対象・介入なし・期限内・現在の legacy 応答0を再確認できる場合だけ、一度オンを要求して1を読み返します。状態不明・対象移動・介入・タイムアウトでは盲目的に書き戻しません。投入が0件または一部だけなら、キー状態も不明なため復元を含む後続操作を止めます。自動再送、追加 Enter、自動キー解放は行わず、手動確認を求めて再試験を停止します。全件投入でも実際の送信成功は不明です。

フック内で待たず、試験を一件だけ作業スレッドで進めます。IME メッセージは各50ms、試験は F1 から500msを期限とし、期限後の処理を再開しません。終了要求後は新規入力を止め、既に変更した場合だけ条件付き復元を試みます。既に投入した場合、終了要求だけで復元用待機を短縮しません。対象変更などでは中止します。終了待ちは最大約1秒で、未確認なら通知します。タイムアウトしても既に投入した入力や設定要求は取り消せず、厳密な時間保証もありません。

**SendInput は特定ウィンドウ宛てではありません。** 確認直後の切替、同じ HWND 内の入力欄変更、未検出の介入による誤送信を完全には防げません。未確定文字を残した場合の確定・取消や、強制終了・クラッシュ時の復元も保証しません。通常権限で実行し、UIPI の回避や権限昇格は行いません。本文・URL・タイトル・変換中文字列・候補は収集せず、変換モードは観測だけです。結果は最新6件をメモリ上に表示し、保存・通信は行いません。

起動中は全アプリの単独 F1 を比較用に抑止します。修飾付き F1 は通過します。CI の **Artifacts → iris-input-trial-windows-x64** を展開して `iris-input-trial.exe` を使用します。ビルド出力は `target/x86_64-pc-windows-msvc/release/iris-input-trial.exe` です。

## API の根拠

- [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc): フックの抑止、タイムアウト、注入イベント。
- [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): 入力の挿入数、UIPI、現在のキー状態。
- [KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput): Unicode 入力。
- [Microsoft windows-rs](https://github.com/microsoft/windows-rs): 使用する `windows-sys` バインディング。
