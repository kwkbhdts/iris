# Iris

Windows 向けの小さな通知領域ツール。通常権限で動かし、修飾キーなしの **F1** を手動で押すと、前面が `Claude.exe` または `firefox.exe` の場合だけ Unicode の `OK` と Enter を送ります。AutoHotkey は不要です。

現在は開発中です。この 100ms 間隔の比較版は、Windows 実機・日本語 IME での動作をまだ確認していません。

## ブランチ方針

- `main`: 確認済みの区切りを置くブランチ。初回は案内のみです。
- `dev`: 実装・テスト・CI を進める開発ブランチです。

Windows 実機で確認できた区切りで、開発コードの `main` への取り込みを検討します。

## 使い方

1. ビルドした `iris.exe` を一つだけ起動します。初期状態は有効です。
2. 対象アプリで、**空の入力欄に自分でフォーカス**します。IME の未確定文字がないことを確認してください。
3. Shift / Ctrl / Alt / Windows キーを離し、F1 を押します。Unicode の `OK` を入力し、タイマーで 100ms 待ってから Enter を一度だけ送ります。長押しや待機中の連打で追加送信はしません。
4. 通知領域のアイコンをクリックすると、「有効」のチェックを切り替えるか「終了」を選べます。状態はアイコンのツールチップでも確認できます。

対象外、無効時、修飾キー付きでは通常の F1 を通します。押し始めに決めた抑止・通過をキーアップまで維持するため、押したまま前面や有効状態を変えても二重動作しません。終了時にフックと通知領域アイコンを解除します。

## 制約

- **空欄・フォーカス・IME 未確定文字なしは使用条件です。アプリは検査しません。** 日本語 IME オン／半角の両方を意図して `KEYEVENTF_UNICODE` を使用していますが、実機では未検証です。IME の状態変更や確定操作は行いません。
- 100ms の固定待機は、文字入力直後の Enter で送信されない現象の原因切り分け用です。Web アプリの更新完了を検知するものではなく、送信成功を保証しません。文字と Enter の間隔以外に、スキャンコード方式や IME 操作は変更していません。
- Firefox は実行ファイル名だけで判定します。すべてのサイト・入力欄・アドレスバーが対象になり得ます。URL 判定、自動フォーカス、通知検知、承認の自動化はありません。
- F1 の抑止は `WH_KEYBOARD_LL` で行います。プロセス名はフック外で確認し、前面変更イベントと 200 ms のタイマーで更新します。前面変更直後など対象が未確認の間は通常の F1 を通します。必要なら前面が落ち着いてから押し直してください。
- 文字と Enter のそれぞれを送る直前に、有効状態、元の前面ウィンドウ・PID・スレッド、実行ファイル名、修飾キー、F1 からの経過時間を再確認します。前面変更、待機中の修飾キー押下、無効化・終了、F1 から 250ms を超えた遅延では予約を破棄します。取消時に `OK` だけが残る場合があります。**SendInput は特定ウィンドウ宛てではないため、確認直後の切替や同一ウィンドウ内の入力フォーカス移動による誤送信を完全には防げません。**
- 他アプリが注入した F1 を含む注入イベントは通過させ、Iris のトリガーとして再処理しません。
- 管理者として動く対象への入力は UIPI により失敗する可能性があります。権限昇格や制限回避は実装しません。送信失敗・一部送信時は無効化し、エラーを表示します。自動再送はしません。入力内容とキー状態を確認してください。
- 実行ファイル名はセキュリティ上の本人確認にはなりません。フックが OS により解除された場合も自動復旧は保証しません。
- 自動起動、設定ファイル、汎用マクロ、通信機能はありません。多重起動の防止は未実装なので一つだけ起動してください。

## ビルドと検証

第一候補は Windows x64 と `x86_64-pc-windows-msvc`。ビルドには Rust と MSVC C++ ビルドツール／Windows SDK が必要です。

```sh
cargo fmt --check
cargo test --locked
cargo check --locked --bins --target x86_64-pc-windows-msvc
cargo build --locked --release --bins --target x86_64-pc-windows-msvc
```

出力は `target/x86_64-pc-windows-msvc/release/iris.exe`。`.cargo/config.toml` で CRT 静的リンクを指定し、追加ランタイム不要の単一 exe を目指します。Windows 標準 DLL は利用します。実際の DLL 依存関係は Windows ビルド後に確認が必要です。

Linux では `cargo test` が F1 の状態遷移と実行ファイル名判定を検証します。Windows 標準ライブラリを備えた Rust なら `cargo check --target x86_64-pc-windows-msvc` で Windows コードの型チェックも可能ですが、exe のリンクには別途 Windows 用のツール／ライブラリが必要です。

## CI と検証範囲

[GitHub Actions の Build](https://github.com/kwkbhdts/iris/actions/workflows/build.yml) は `main` / `dev` への push と、それらに向けた pull request で動きます。

- Linux ジョブ: `cargo fmt --check` とロジックテスト（通常版14件・診断版6件・切替試験版16件、共通診断の6件を再実行）を実行します。100ms の待機、二重送信防止、取消、古いタイマー通知、期限切れも対象です。
- Windows ジョブ: `x86_64-pc-windows-msvc` の release exe をビルドします。CRT 静的リンクは `.cargo/config.toml` の指定を使用します。
- exe は各 run の **Artifacts → iris-windows-x64** から取得できます（保存期間14日）。開発用成果物であり、リリース版ではありません。

各コミットの CI 成否は Actions で確認してください。依存バージョンは `Cargo.lock` に固定しています。Linux 上での整形・ロジックテスト・Windows 向け型チェックは確認済みですが、型チェックには exe のリンクや実行は含まれません。

**Windows でビルドできても、実機の通知領域・フック・入力送信・日本語 IME の動作確認にはなりません。これらは未検証です。** CI は Iris の常駐開始や実際のチャット送信を行いません。

実機検証は、実際にチャットを送信しない Firefox のローカル HTML 入力欄などから始めてください。IME オン／半角（未確定文字なし）、長押し、連打、各修飾キー、対象外アプリ、前面切替、有効切替、終了後の F1、通常権限から高い権限の対象への失敗を確認します。Claude 固有の入力動作は別途、送信を許可した環境での確認が必要です。

この比較版では特に、待機中の前面切替・修飾キー押下・無効化・終了で Enter が取り消されること、取消後に対象へ戻っても古い Enter が届かないことを確認してください。タイマーの実際の発火時刻やブラウザのイベント処理は、Linux のロジックテストでは検証していません。

## 読み取り専用の診断版

`iris-diagnostic.exe` は通常版とは別の実行ファイルです。文字入力・Enter 送信・IME の切替・未確定文字の確定や取消は行いません。通常版の入力処理は変更していません。

1. 通常版を通知領域の「終了」で閉じ、診断版を一つだけ起動します。診断中に通常版を起動しないでください。起動時には通常版との重複を確認しますが、その後の同時起動による入力送信は防げません。
2. 対象アプリの入力欄へ自分でフォーカスし、**半角 → 日本語入力（未確定文字なし）→ 未確定文字あり**の順に、各状態で単独 F1 を一度押します。各結果が表示されてから次に進みます。実際のチャット送信は不要です。
3. 診断ウィンドウの「結果を選択 → Ctrl+C」を押し、Ctrl+C でコピーします。必要なら各サンプルの状態を自分で添えて貼り付けてください。ウィンドウを閉じると終了してフックを解除します。

診断版が起動している間は、**対象外を含むすべてのアプリで単独 F1 を診断用に抑止**します。修飾キー付き F1 は通します。長押し・採取待ち中の連打・注入イベントでは追加採取しません。通常版の対象外 F1 の動作には変更ありません。

表示するのは F1 時点の前面／フォーカス HWND・PID・スレッド ID、実行ファイルのベース名、後続の問い合わせ時点のキーボードレイアウトと IME ウィンドウ情報、従来の IMM 互換問い合わせの生の応答です。プロセスの照会／メモリ読み取り権限はモジュールのベース名取得に使い、本文・タイトル・URL・ファイルのフルパス・変換中文字列・候補は収集しません。最新6件をメモリ上に表示するだけで、ファイル保存・通信・自動クリップボード操作は行いません。

IME 問い合わせは対象プロセス名とウィンドウの所有者を確認した上で、フック外の単一作業スレッドから行います。他プロセスの入力コンテキストを自プロセスの IMM 関数へ渡しません。各メッセージの待ち時間は50ms、結果採用の期限は F1 から500msです。遅れて戻った結果は破棄します。OS の処理や UI タイマーの実行時刻について厳密な時間保証はありません。

**生の応答が0でも「IME オフ」「未確定文字なし」とは判定しません。** 従来の問い合わせに対する現行 IME の対応は保証されず、TSF の実際のオン／オフと未確定文字の有無は常に不明と表示します。失敗・タイムアウト・未取得も不明です。レイアウトの値だけでも IME 状態は判断できません。採取前後のウィンドウ識別情報が一致しても、同じ HWND 内の入力欄変更や一瞬の前面切替は検出できず、全項目の同時取得も保証しません。

診断版は `target/x86_64-pc-windows-msvc/release/iris-diagnostic.exe` に出力されます。CI の追加成果物名は **iris-diagnostic-windows-x64** です。この診断版の Windows 実機動作と IME 応答は未検証です。

## IME 切替・復元だけの試験版

**`iris-ime-trial.exe` は IME の状態を変更する実験版です。文字入力・Enter・チャット送信は一切行いません。** 通常版と読み取り専用診断版の動作は維持しています。Windows 実機での切替・復元は未確認です。

1. **通常版 Iris と読み取り専用診断版を終了**し、試験版を一つだけ起動します。試験中に他の Iris を起動しないでください。
2. Claude Desktop または Firefox の**空の入力欄・未確定文字なし**を自分で確認してフォーカスします。今回は変換途中の文字を残して試さないでください。
3. 日本語入力をオンにし、修飾キーを離して F1 を一度押します。**結果が出るまでキー・マウスに触れないでください。** 半角での比較は状態変更を行わないことの確認です。
4. 結果が表示された後、「結果を選択 → Ctrl+C」でコピーします。最後に元の入力欄の IME 状態を自分で確認してください。手動確認が必要と表示されたら、自分で復元し、試験版を終了してください。再試験には再起動が必要です。

元の `legacy_open` が正確に1の場合だけ、同じ IME ウィンドウへ従来の `IMC_SETOPENSTATUS` によるオフ要求を送り、応答0を読み取った後に約100ms待ってオンへの復元を試みます。元が0・不明・取得失敗なら変更しません。現行 IME での設定コマンドの対応は保証されません。設定の生の戻り値0を候補とし、設定後の読み取り応答も照合します。`legacy_1_0_1_observed` は従来の応答の往復を観測した意味で、TSF の実際の状態や完全な復元の証明ではありません。変換モードは前後の観測だけで、書き戻しません。

各操作前に、前面・フォーカス HWND/PID/スレッド、対象の実行ファイル名、IME ウィンドウと所有者、レイアウト、経過時間を再確認します。キーボード・マウス操作（移動を含む）、前面・フォーカス変更イベントは内容を保存せず、試験への介入として扱います。移動後に元へ戻っても処理を再開しません。バックグラウンドのフォーカスイベントでも保守的に中止する場合があります。フック内で待機やプロセス・IME 問い合わせはせず、単一作業スレッドで一件ずつ処理します。

- オフ要求前の取消では書き込みません。
- オフ要求後は、介入なし・同じ対象／レイアウト・期限内・現在の応答0を再確認できた場合に限り、オンへの復元を一度だけ試みます。状態不明、対象移動、介入、タイムアウトでは盲目的に書き戻さず、手動確認を求めます。
- メッセージの待ち時間は各50ms、試験の期限は F1 から500msです。期限切れでも作業が戻るまで次の試験は開始しません。タイムアウトした設定要求も、後から反映される可能性を否定できません。待ち時間の制限は状態変更の取消ではありません。
- 終了要求は新規のオフを止め、既に変更した場合だけ上記条件で復元を試みます。×を押す操作自体も介入・前面変更となり、復元を中止する場合があります。作業の終了待ちは最大約1秒とし、未確認なら通知して終了します。OS の応答・タイマー時刻の厳密な保証はありません。
- **強制終了・クラッシュ時の復元は保証できません。** 未確定文字が残っていた場合には、切替で確定・取消などが起こる可能性があります。未確定文字の有無は検出せず、本文・URL・タイトル・変換中文字列・候補は収集しません。
- 同じ HWND 内の入力欄の切替、届かないイベント、確認直後の競合は完全には検出できません。手動操作の完全な識別や設定の原子的な復元は保証しません。結果が不明なら自動で再試行せず、終了・手動確認後に再起動してください。

起動中は全アプリの単独 F1 を抑止します。修飾付き F1 は通過しますが、試験中の修飾キー操作は取消要因です。結果は最新6件をメモリ上に表示するだけで、通信やファイル保存はしません。

CI の **Artifacts → iris-ime-trial-windows-x64** を展開し、`iris-ime-trial.exe` を使用します。通常版・読み取り専用診断版の成果物も引き続き生成します。ビルド出力は `target/x86_64-pc-windows-msvc/release/iris-ime-trial.exe` です。

## API の根拠

- [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc): フックの抑止、タイムアウト、注入イベント。
- [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): 入力の挿入数、UIPI、現在のキー状態。
- [KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput): Unicode 入力。
- [Microsoft windows-rs](https://github.com/microsoft/windows-rs): 使用する `windows-sys` バインディング。
