# Iris

Windows x64 向けの小さな通知領域ツールです。対象アプリを前面にして **修飾キーなしの F1** を押すと、IME の状態応答を確認し、Unicode の `OK` と Enter を一度送ります。AutoHotkey や追加ランタイムのインストールは不要です。

## ダウンロードと使い方

[Releases](https://github.com/kwkbhdts/iris/releases) から `iris.exe` を取得してください。ライセンス表示の `THIRD_PARTY_NOTICES.txt` と `RUST-LIBRARY.html` も一緒に保管してください。`SHA256SUMS.txt` で添付ファイルの SHA-256 を確認できます。

1. 起動中の古い Iris を終了し、`iris.exe` を一つだけ起動します。初期状態は有効です。
2. 対象アプリの**送信してよい入力欄**へ自分でフォーカスし、**空欄・IME の未確定文字なし**を確認します。
3. Shift / Ctrl / Alt / Windows キーと Enter を離し、F1 を一度押します。入力・復元が終わるまでキーやマウスに触れないでください。長押し・処理中の連打では追加送信しません。
4. 通知領域の Iris アイコンをクリックし、「有効」のチェックを切り替えるか「終了」を選べます。無効時・対象外・修飾キー付きでは通常の F1 を通します。

入力や IME 復元を確認できないときは、Iris を無効化して理由を表示します。入力・送信結果、キー状態、元の入力欄の IME を手動確認・復元してから再び有効にしてください。未完了の処理がある間は再有効化できません。

## 対象アプリ

| アプリ | 前面プロセスの実ファイル名 |
| --- | --- |
| Claude Desktop | `Claude.exe` |
| Firefox | `firefox.exe` |
| Google Chrome | `chrome.exe` |
| ChatGPT Desktop | `ChatGPT.exe` |

名前は大文字小文字を区別せず、末尾の実ファイル名が完全一致するときだけ対象にします。製品メタデータや OriginalFilename は使わず、`codex.exe` は対象外です。

**Firefox と Chrome はブラウザ全体が対象**です。URL・サイト・入力欄の種類を限定せず、アドレスバーも対象になり得ます。空欄・未確定文字なし・正しいフォーカスは利用者が確認する条件であり、Iris は検査しません。自動フォーカス、通知検知、承認の自動化はありません。

## IME と待機時間

- 元の legacy 開閉応答が0なら、0を再確認して入力し、IME を切り替えません。
- 元が1なら一時オフを要求し、0を読み返せた場合だけ入力します。状態が不明なら送信しません。
- **OK と Enter の間に追加待機はありません。** 押下・解放を含む6イベントを一度だけ SendInput に投入します。
- 元が1で全イベントを投入できた場合だけ、**投入後の暫定100ms**を経て、同じ対象・介入なし・期限内・現在の応答0を再確認できる場合にオンへ復元し、1を読み返します。

100ms は復元前だけの実験値です。必要性・十分性は未立証で、アプリが入力を処理し終えたことを保証しません。SendInput の成功も投入数を示すだけで、入力先やチャット送信成功の確認ではありません。legacy 応答から TSF の実際の状態や未確定文字の有無を完全に判断できるとは主張しません。

## 中止・復元の制約

- 前面・フォーカス、PID・スレッド、実行ファイル名、IME の所属、レイアウト、修飾キー、期限を各操作前に再確認します。キーボード・マウス操作（移動を含む）、前面・フォーカス変更を介入として扱います。一度中止した処理は、元へ戻っても再開しません。背景のフォーカスイベントで保守的に中止する場合もあります。
- 無効化・終了は新規入力を止めます。既に IME をオフにしていた場合は上記の条件が保たれるときだけ復元します。トレイ操作自体も介入となり、復元を中止する場合があります。
- IME メッセージは各50ms、処理は F1 から500msを期限とします。期限切れでは無効化して手動確認を知らせます。作業が戻るまで次を開始せず、終了待ちは最大約1秒です。OS の応答やタイマー時刻の厳密な保証はありません。
- 状態不明・対象移動・介入・一部投入では盲目的に書き戻しません。自動再送、追加 Enter、自動キー解放は行いません。投入済みの入力や設定要求は取り消せず、タイムアウトした要求が後から反映される可能性があります。
- **SendInput は特定ウィンドウ宛てではありません。** 確認直後の前面切替や同じ HWND 内の入力欄変更による誤送信を完全には防げません。未確定文字が残っている場合は確定・取消などが起こり得ます。強制終了・クラッシュ時の IME 復元は保証できません。
- 前面候補はフック外の照会と200msタイマーで更新します。切替直後など対象未確認の間は F1 を通します。必要なら前面が落ち着いてから押し直してください。
- 通常権限で使います。管理者権限の対象への入力は UIPI で失敗し得ますが、昇格や回避は行いません。実行ファイル名はセキュリティ上の本人確認ではありません。フックが OS に解除された場合の自動復旧も保証しません。
- 本文・URL・タイトル・変換中文字列・候補は収集しません。通信、記録ファイル、設定ファイル、自動起動登録、汎用マクロ機能はありません。

## 確認できた範囲

- Claude Desktop / Firefox：入力比較版 `3eb7609` で、利用者が半角・日本語入力のそれぞれで送信成功を確認しました。元オフは6/6投入・IME書き込みなし。元オンは1→0→入力→1、変換モードは前後0x19、処理時間125msで、復元用100msを含む条件です。
- ChatGPT Desktop / Chrome：対象追加版 `4034eb1` で、利用者から送信成功の報告があります。IME 条件の網羅確認は未実施です。
- これらは当該環境・試験時の入力欄での利用者報告です。全バージョン・全入力欄での動作や TSF の一般的な保証ではありません。v0.1.0 の配布 exe をこのクラウド環境で起動したり、実際のチャット送信を行ったりはしていません。

更新後は、送信してよい場所で空欄・未確定文字なしを確認し、半角／日本語で各1回送信と IME 復帰を確かめてください。対象外 F1、有効／無効、長押し、終了後の通常動作も確認してください。

## 開発・ビルド

Rust 1.99.0、`x86_64-pc-windows-msvc`、MSVC C++ ビルドツール／Windows SDK を使用します。

```sh
cargo fmt --check
cargo test --locked
cargo check --locked --target x86_64-pc-windows-msvc
cargo build --locked --release --bin iris --target x86_64-pc-windows-msvc
```

出力は `target/x86_64-pc-windows-msvc/release/iris.exe` です。CRT は静的リンクし、Windows 標準 DLL は利用します。Linux ではロジックテストと Windows 向け型チェックが可能ですが、MSVC のリンク・ビルドは Windows CI で行います。CI は exe を起動しません。

`dev` で変更を検証し、PR のレビューと CI 確認後に `main` へマージします。[Build CI](https://github.com/kwkbhdts/iris/actions/workflows/build.yml) は通常版のみをビルドし、`iris-windows-x64` に exe・ライセンス表示・ハッシュを保存します。診断・比較用アプリのソースは Git 履歴に残っていますが、現在の配布対象には含めません。

[Release CI](https://github.com/kwkbhdts/iris/actions/workflows/release.yml) は、タグが main の正確なコミットを指し、そのコミットの Build が成功していることを確認してから、同じソースをビルドして正式リリースへ添付します。別 workflow の artifact 再取得は行いません。`GITHUB_TOKEN` の `actions:read` は CI 確認、`contents:write` はリリース作成に限定して使い、公開した添付ファイルを再ダウンロードしてハッシュを照合します。

## ライセンス表示

依存クレートの表示は [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt) にあります。配布物にはビルドに使った Rust 標準ライブラリの著作権・ライセンス原文 `RUST-LIBRARY.html` も添付します。Iris 本体の新しいライセンスをこの作業で設定するものではありません。
